# Data README

## Dataset

### Online Retail II

This project uses the **Online Retail II** dataset from the **UCI Machine Learning Repository**.

- **UCI dataset page:** https://archive.ics.uci.edu/dataset/502/online%2Bretail
- **DOI:** 10.24432/C5CG6D
- **License:** Creative Commons Attribution 4.0 International (CC BY 4.0)
- **Reported raw size:** 1,067,371 transaction records across 9 original columns
- **Reported date coverage:** 2009-12-01 to 2011-12-09
- **Identified customers:** 5,942
- **Countries:** 43

The original workbook contains two sheets of Online Retail II transaction records.

## How to obtain the data

Download the dataset from the official UCI page:

https://archive.ics.uci.edu/dataset/502/online%2Bretail

Place the downloaded original Excel workbook **unchanged** in:

```text
data/raw/
```

Expected layout:

```text
data/
├── raw/
│   └── <original Online Retail II .xlsx file>
├── processed/
└── README.md
```

Do not modify the original source workbook before the notebooks read it.

## Expected raw fields

The source transaction data include fields corresponding to:

- `Invoice`
- `StockCode`
- `Description`
- `Quantity`
- `InvoiceDate`
- `Price`
- `Customer ID`
- `Country`

The preprocessing workflow combines the two source sheets and adds `SourceSheet` so the source sheet can be tracked.

## How the project uses the data

The preprocessing and feature-engineering workflow:

1. loads the two source sheets;
2. combines them into one transaction table;
3. audits missing values, duplicates, cancellations, and invalid values;
4. removes exact duplicate rows;
5. identifies customer-usable purchase transactions;
6. constructs transaction-level value measures;
7. creates customer-level behavioral features using the preceding 180 days;
8. creates `return_30d` using the following 30 days.

The final modeling transaction subset contains **793,609 customer-identifiable purchase transactions** after the purchase-specific filtering used in the supplied notebooks.

## Missing customer identifiers

Many raw transactions do not contain a `Customer ID`. These rows are retained during the broader data audit, but they cannot be assigned to a customer history and therefore cannot be used for customer-level predictive modeling.

The raw dataset contains approximately **243,007 rows with missing Customer ID** before final customer-level filtering.

## Processed data

Files generated by the notebooks should be placed under:

```text
data/processed/
```

Processed files should be treated as generated outputs. When a transformation changes, rerun the relevant notebook rather than manually editing generated data.

## Data handling rules

- Keep the original source workbook in `data/raw/`.
- Do not alter the raw source file.
- Keep generated files in `data/processed/`.
- Use repository-relative paths only.
- Do not commit machine-specific paths or temporary/cache files.
- Document any additional external or derived dataset in this README.
- The UCI source is distributed under CC BY 4.0.
